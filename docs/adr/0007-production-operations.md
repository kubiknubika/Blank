# ADR-0007: Production operations — rate limiting, metrics, probes, contract, backups, E2E

Date: 2026-11-04
Status: Accepted

## Context

After correctness (ADR-0005) and concurrency (ADR-0006), the remaining gap to
"actually operable in production" was the layer around the request handlers:
abuse protection, scrapeable telemetry, honest health probes, a machine-readable
API contract, a backup story for the single SQLite file, and an end-to-end test
that exercises the artifact users really get. This ADR records the choices and
their trade-offs. The dependency tree stays lean: **zero new runtime
dependencies** — everything below is hand-built on Node and Express primitives,
and the one dependency change was a security upgrade (zod 3 → 4).

## Decisions

### 1. Fixed-window per-IP rate limit on mutations only

`server/src/http/rateLimit.ts` — an in-memory fixed-window counter keyed by
`req.ip`. Defaults: **120 mutations / 60 s**, configurable via `RATE_LIMIT_MAX`
(0 disables) and `RATE_LIMIT_WINDOW_MS`.

- **Mutations only** (POST/PUT/PATCH/DELETE). Reads, health probes and scrapes
  are never limited: a dashboard polling loop must not lock itself out, and a
  Kubernetes probe storm must not eat the user's budget.
- **Before body parsing.** A flood of 429s costs a Map lookup, not a JSON parse
  (test-pinned: over-budget requests with malformed JSON still get 429, not 400).
- **429 + `Retry-After`** plus `X-RateLimit-Limit/Remaining/Reset` headers, and a
  coded `RATE_LIMITED` error body consistent with every other API error.
- **Memory is bounded**: expired buckets are swept lazily once per window and a
  10 k-key cap forces a sweep, so spoofed-IP spray cannot grow the Map forever.
- **Proxy correctness**: `TRUST_PROXY_HOPS` (default 0) maps to Express
  `trust proxy`. With 0, `X-Forwarded-For` is ignored — a client cannot mint
  fresh buckets by spoofing the header (test-pinned). Behind one ingress, set 1.
- **Trade-offs accepted**: fixed windows allow a burst of up to 2× at a window
  boundary (vs sliding log's exactness) — fine for an abuse brake, not a billing
  meter. In-memory state means the budget is per-process; the multi-instance
  upgrade path is a Redis-backed limiter with the same middleware shape.

### 2. Hand-rolled Prometheus metrics, cardinality-safe by construction

`server/src/observability/metrics.ts` — a small registry rendering the text
exposition format at `GET /api/metrics` (`METRICS_ENABLED=false` → 404).

- `http_requests_total{method,route,status}` counter and
  `http_request_duration_seconds` histogram (fixed buckets 5 ms … 10 s), plus
  `process_uptime_seconds`, `process_resident_memory_bytes` and an
  `offerflow_applications` gauge computed at scrape time.
- **The `route` label is the matched Express route pattern**
  (`/api/applications/:id`), never the URL — otherwise every application id
  would mint a new time series and melt the scraper. Unknown paths collapse to
  `/api/unmatched`; non-standard methods collapse to `OTHER`. Both are
  test-pinned, including "the id never appears in the exposition output".
- Express restores `req.baseUrl` when the stack unwinds on errors, so the
  `/api` prefix is applied by the middleware itself, not read at finish time
  (a real bug caught by the tests: error responses were losing the prefix).
- Why not `prom-client`? The needs are two metric families and a gauge; the
  registry is ~120 lines, auditable, and dependency-free. If the app grows
  event-loop lag / GC metrics, swap in prom-client behind the same endpoint.

### 3. Liveness ≠ readiness, and draining flips readiness first

- `GET /api/health` — liveness: process up, DB handle answering (unchanged).
- `GET /api/ready` — readiness: 200 `{status:"ready"}` normally; 503
  `{status:"draining"}` the instant SIGTERM/SIGINT arrives; 503
  `{status:"unavailable"}` if the DB check fails.
- Graceful shutdown now sets `lifecycle.draining = true` **before**
  `server.close()`, so a load balancer stops routing new traffic while in-flight
  requests still complete. Docker's HEALTHCHECK intentionally stays on
  `/api/health`: a draining container is healthy, just not routable.

### 4. OpenAPI 3.1 generated from the live contract, with drift tests

`server/src/http/openapi.ts` serves `GET /api/openapi.json`.

- Request bodies are generated by **zod 4's `z.toJSONSchema`** from the exact
  schemas the routes validate with (`io: "input"`; `z.preprocess` pipes are
  overridden to document the post-preprocess schema — the meaningful side).
  OpenAPI 3.1 accepts JSON Schema 2020-12 natively, so no dialect down-conversion.
- Response models are hand-written but typed
  `satisfies Record<keyof Application, …>` against the shared interfaces:
  adding a field to the type **breaks compilation** until the contract is
  updated.
- `server/tests/openapi.test.ts` closes the loop at runtime: it walks the real
  Express router (every route documented, no phantoms), compares contract
  property keys with **live supertest responses** (create/read/patch/events/
  analytics/error), and pins the documented headers (`ETag`, `If-Match`,
  `Retry-After`, `X-Total-Count`). These tests already caught two real drifts
  while being written: create/patch return `ApplicationWithEvents`, not bare
  `Application`.

### 5. Online backups via `VACUUM INTO`, verified on write

`server/scripts/backup.mjs` (`npm run backup`, also copied into the Docker
image).

- The DB runs in WAL mode, so `cp offerflow.db` can capture a stale or torn
  state — the freshest commits may still be in the `-wal` sidecar.
  `VACUUM INTO ?` takes a **transactionally consistent, compacted snapshot
  while the server keeps writing** (test-pinned with a live connection).
- The source is opened read-only and `quick_check`ed first; the snapshot is
  reopened and `integrity_check`ed + row-counted after. A backup you never
  verified is a hope, not a backup.
- Refuses to overwrite the target (both in the script and, inherently, in
  SQLite). Restore = stop the app, point `DB_PATH` at the snapshot (or copy it
  over), start. Cron example: `0 3 * * * cd /app && node server/scripts/backup.mjs`.

### 6. Playwright E2E against the production artifact — CI-only browsers

`playwright.config.ts` + `tests/e2e/offerflow.spec.ts`, run as a separate CI job.

- The webServer runs `npm run build && npm start` with `NODE_ENV=production`,
  a fresh seeded `e2e.db` (global setup deletes WAL sidecars too) and port 3100
  — the same code path as the Docker image, including the strict security
  checks (no dev loopback exemptions).
- Six golden-path tests: board load, create → drawer status move → search →
  dashboard, edit persistence across reload, **server-side** validation
  round-trip (salaryMin > salaryMax passes HTML but fails the zod refine),
  delete with confirm dialog, demo reset. Serial (workers=1): one SQLite file,
  determinism over wall time.
- Browser binaries are installed only in CI (`npx playwright install
--with-deps chromium`) — never a postinstall hook, so `npm ci` stays
  registry-only and the sandbox/dev machines need no browser.
- Writing these surfaced a real UX bug, now fixed and unit-pinned: saving an
  edit left an open DetailDrawer showing stale data. The drawer now takes a
  `refreshKey` and reloads in place — without a loading flash, and still
  without refetching on unrelated parent re-renders.

### 7. Supply chain: zod 3 → 4, audit gate, dependabot

- `npm audit --omit=dev` reported **GHSA-mrhx-c7xc-m3w5** (high): zod < 4.6.6
  can exhaust memory validating oversized constrained collections — and zod
  parses every untrusted request body here. Upgraded to zod ^4.6.7; the
  migration was two API renames (`error.errors` → `error.issues`) plus the
  `toJSONSchema` opportunity above. All 158 tests pass unchanged otherwise.
- CI now gates on `npm audit --omit=dev --audit-level=high`: production
  advisories block merges; dev-only advisories are dependabot's job, not a
  merge blocker.
- `.github/dependabot.yml`: weekly grouped npm + github-actions updates.

### 8. HTTP cache policy

All `/api` responses: `Cache-Control: no-store` (per-request state must never
be cached by intermediaries). Vite's content-hashed `assets/*`:
`public, max-age=31536000, immutable`. `index.html` and the SPA fallback:
`no-cache` — revalidate so deploys take effect immediately.

## Consequences

- The app is now operable: scrape it, probe it, back it up, read its contract,
  and survive a scripted flood — with the same lean dependency tree.
- 158 unit/integration tests + 6 E2E tests; CI adds an audit gate and an E2E
  job on the production build.
- Deliberate non-goals: per-user quotas (no auth yet), distributed rate-limit
  state, metric auth (scrape endpoint is unauthenticated like the rest of the
  API; put it behind the ingress allowlist if that changes), scheduled
  in-process backups (cron/K8s CronJob owns scheduling, not the app).
